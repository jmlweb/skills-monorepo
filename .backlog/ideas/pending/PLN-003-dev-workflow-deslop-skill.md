## Goal
Remove LLM-style comments and prose from the current branch diff, keeping only comments that explain why.

## Context
Usage analysis: ~20 corrections ("remove all the comments clearly generated by LLM", "implementation details can be read from the code", "I still see a lot of prose"). ponytail-review targets over-engineered code; atlassian-polish targets Jira/Confluence. Nothing targets comments and prose in a git diff.

## Approach
1. Scope to added lines in the branch diff vs base (`git diff <base>...HEAD`).
2. Flag: comments restating the code, boilerplate JSDoc on obvious signatures, change-log comments ("// updated to fix X"), section-banner noise, marketing tone.
3. Keep: why-comments, invariants, workarounds with links, public API docs required by lint.
4. Show a numbered list; apply only the selected removals.
5. Optional `--pr`: trim the PR body the same way (confirm before `gh pr edit`).

# GitHub Posting Rules (shared by skills that write to GitHub)

Apply before any command that creates or changes something on GitHub
(issues, comments, reruns, PRs, reviews).

## Confirm first

- Show the exact title and body (or the exact command) and wait for an explicit yes.
- One confirmation covers one action; ask again for the next one.
- Reads (`gh ... view`, `gh ... list`) never need confirmation.

## Content

- Write in English in a plain, factual tone: no hype, no emoji.
- Add attribution lines ("Generated with…", tool or AI signatures) only when the user's
  or the project's settings call for them.

## Git safety

- Ask before pushing to the base branch.
- Ask before force-pushing.
